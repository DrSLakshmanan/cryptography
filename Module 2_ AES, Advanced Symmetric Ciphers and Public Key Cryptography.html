Introduction and evaluation criteria

DES was too small for modern attackers, and 3DES was slow. In 1997 NIST opened a public competition. Rijndael, designed by Joan Daemen and Vincent Rijmen, won and became AES in 2001 (FIPS 197). Candidates were judged on three groups of criteria.

AES cipher: encryption and decryption

AES processes a 128-bit block in rounds. The key size decides the number of rounds. Choose a key size to see the schedule. The last round skips MixColumns. Decryption applies the inverse operations in reverse order, with the round keys also reversed.

AES data structure

The 16 bytes of a block fill a 4×4 state matrix column by column, so byte i goes to row i mod 4, column ⌊i/4⌋. The key is expanded into 4(Nr+1) 32-bit words, giving one 128-bit round key per round plus one extra. Type 16 characters to see them placed.

AES encryption round

Each round has four stages. SubBytes replaces every byte through the S-box (confusion). ShiftRows rotates row r left by r bytes. MixColumns multiplies each column by a fixed matrix over GF(28), which with ShiftRows gives diffusion. AddRoundKey XORs the state with the round key. The default values are the first round of the FIPS-197 worked example. Click a stage; yellow bytes changed from the previous stage.

Multiple encryption and Triple DES

Double DES looks like 112 bits but the meet-in-the-middle attack encrypts forward under every K1 and decrypts backward under every K2, then matches the middle value. This costs about 257 work, not 2112. Triple DES uses encrypt-decrypt-encrypt: C = E(K3, D(K2, E(K1, P))). With K1 = K2 = K3 it behaves as single DES, which keeps old systems compatible. It is now deprecated in favour of AES.

Stream ciphers and RC4

A stream cipher XORs the data with a pseudo-random keystream, bit by bit or byte by byte. Never reuse a keystream: XORing two ciphertexts then cancels the key and leaves P1 XOR P2. RC4 keeps a 256-byte array S. The key-scheduling step (KSA) permutes S using the key. The generation step (PRGA) swaps two entries per output byte. RC4 has known biases and is banned in TLS, but it is the classic teaching example. Default input is the standard test vector (key “Key”, text “Plaintext”, output BBF316E8D940AF0AD3).

Principles of public key cryptosystems

Each user has a public key to share and a private key to keep. What one key does, only the other undoes. This solves key distribution but is slow, so it is used for key exchange and signatures while symmetric ciphers carry the data. Security depends on a one-way trapdoor function, such as factoring the product of two large primes. Switch the use below.

The RSA algorithm

Choose primes p and q, then n = p·q and φ(n) = (p−1)(q−1). Pick e coprime to φ(n) and find d with e·d ≡ 1 (mod φ(n)). The public key is (e, n), the private key is (d, n). Encrypt C = Me mod n. Decrypt M = Cd mod n. A signature reverses the keys: S = Md mod n, verified with Se mod n. Real keys use 2048 bits or more plus padding.

Key management

Public keys need distributing too, and the main risk is trusting a fake one. Four approaches:

Public announcementPost the key openly. Simple, but anyone can forge a post.
Public directoryA trusted party keeps a register. The directory itself becomes a target.
Public-key authorityAn authority answers key requests and signs replies. Every lookup needs the authority online.
CertificatesA CA signs a binding of name and public key (X.509). Users verify offline.

Diffie-Hellman key exchange

Alice and Bob agree on a prime p and a generator g. Alice sends A = ga mod p and Bob sends B = gb mod p. Each computes the same secret gab mod p. Eve sees p, g, A, B, but recovering a or b is the discrete logarithm problem. Plain DH does not authenticate, so Eve can sit in the middle with a separate key to each side, unless the exchange is signed.

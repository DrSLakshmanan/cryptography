Authentication requirements

Encryption hides content, but it does not prove who sent a message or that it is unchanged. Authentication defends against these attacks on communication.

Authentication functions

Every scheme has a low-level function that produces an authenticator and a higher-level protocol that uses it. Three families of function exist.

Message encryptionThe ciphertext itself is the authenticator. With symmetric keys only the key holders could have made it, but the receiver needs redundancy in the plaintext to recognise a valid message.
Message authentication codeA short tag computed from message and a shared key. The message can stay in clear text.
Hash functionA fixed-size digest of the message with no key. It must be protected, for example by encryption or a signature.

Hash functions

A hash H maps any input to a fixed-size digest. Three properties matter: preimage resistance (given h, finding M is hard), second-preimage resistance (given M1, finding M2 with the same hash is hard) and collision resistance (finding any pair is hard). By the birthday paradox, collisions in an n-bit hash need only about 2n/2 tries, so a 256-bit hash gives 128-bit collision security. Type a message. The second text differs by one flipped bit in its first character, and yellow marks the hex digits that changed (the avalanche effect).

SHA-256 pads the message with a single 1 bit, then zeros, then the 64-bit message length, so the total is a multiple of 512 bits. Each block runs 64 rounds of a compression function on eight 32-bit variables, chained from the previous digest. Enter a message length to see the padding.

Message authentication codes and HMAC

A MAC is T = MAC(K, M). The receiver recomputes the tag and compares. It gives integrity and origin authentication but not nonrepudiation, since both sides hold K. HMAC builds a MAC from a hash: HMAC(K, M) = H((K′ ⊕ opad) ∥ H((K′ ⊕ ipad) ∥ M)), where K′ is the key padded to the 64-byte block, ipad is 0x36 repeated and opad is 0x5C repeated. The nesting blocks length-extension attacks that break H(K ∥ M). Below, HMAC-SHA256 is built by hand and checked against the browser’s own.

CMAC

CMAC makes a MAC from a block cipher such as AES. Message blocks are chained as in CBC, but the last block is XORed with a derived subkey first: K1 if the last block is complete, K2 if it needed padding (10…0). Plain CBC-MAC is only safe for fixed-length messages, and the subkeys fix this for any length. Only the final cipher output (or its leftmost bits) is kept as the tag.

M1 → E(K)⊕ M2 → E(K)⊕ M3 → E(K)⊕ M4 ⊕ K1 or K2 → E(K)Tag T

Digital signatures

A signature gives authentication, integrity and nonrepudiation, because only the owner holds the private key. The signer hashes the message and signs the digest; anyone verifies with the public key. The demo uses the toy RSA key from the lab (n = 3233, e = 17, d = 2753) and shrinks the hash to a number below n, so many messages collide. Real signatures use 2048-bit keys and padding.

Authentication protocols

Protocols add freshness to the functions above so old messages cannot be replayed. A timestamp needs synchronised clocks. A nonce challenge-response needs none. Three-step mutual authentication with a shared key K:

1 A → B: IDA ∥ Na2 B → A: E(K, Na ∥ Nb)3 A → B: E(K, Nb)

A sees its own Na returned, so B is live and holds K. B sees Nb returned, so A does too. Fresh random nonces defeat replay.

Digital Signature Standard (DSS)

FIPS 186 specifies DSA, RSA and ECDSA. DSA uses a prime p, a prime q dividing p−1 and a generator g of order q. The private key is x and the public key y = gx mod p. To sign hash H with a fresh secret k: r = (gk mod p) mod q and s = k−1(H + x·r) mod q. To verify: w = s−1, u1 = H·w, u2 = r·w and v = (gu1·yu2 mod p) mod q, valid if v = r. Reusing or leaking k reveals x. Toy parameters p = 23, q = 11, g = 4.

Kerberos

Kerberos authenticates clients to services with symmetric keys and a trusted server, so passwords never cross the network. The client gets a ticket-granting ticket (TGT) once, then a service ticket for each server. Select a message.

X.509 authentication service

X.509 defines the certificate that binds a public key to an identity, signed by a certification authority (CA). Click a field.

A browser trusts a certificate if its signature verifies against the issuer’s key and the chain ends at a root it already trusts. Revocation uses a Certificate Revocation List (CRL) or live OCSP queries.

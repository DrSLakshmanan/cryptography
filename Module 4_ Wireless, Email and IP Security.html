Wireless security

Wireless traffic travels through open air, so anyone in range can listen, and devices can join without plugging in. Wireless LANs, cellular links and mobile devices therefore need protection that wired networks get partly from physical access. Select a threat to see the defence.

General countermeasures: strong link encryption (WPA2 or WPA3), mutual authentication through 802.1X, hiding nothing behind the SSID alone, signal-range control, wireless intrusion detection and VPNs on untrusted networks.

IEEE 802.11i wireless LAN security

WEP used RC4 with a 24-bit IV and was broken in minutes. WPA was a stopgap with TKIP. 802.11i (WPA2) uses AES-based CCMP. WPA3 replaces the pre-shared key exchange with SAE, which resists offline guessing.

Internet mail architecture and email formats

A message leaves the author’s Mail User Agent (MUA), goes to a Mail Submission Agent (MSA), is relayed by Message Transfer Agents (MTAs) using SMTP, reaches a Mail Delivery Agent (MDA) and lands in a message store that the recipient reads through IMAP or POP3. Select a component.

A message follows RFC 5322: header lines, a blank line, then the body in 7-bit ASCII. MIME adds headers that describe other content (images, attachments, non-ASCII text) and encodes it, usually in base64. Edit the fields to see the raw message.

No single control covers all of these, so email security is layered: transport (STARTTLS, DANE), message (S/MIME or PGP), domain (SPF, DKIM, DMARC) and content (spam and malware filters). DMARC ties SPF and DKIM to the visible From domain and tells receivers to reject, quarantine or accept failures.



S/MIME and Pretty Good Privacy


Both give authentication, integrity and confidentiality at message level. S/MIME uses X.509 certificates from CAs and CMS data types. PGP uses OpenPGP keys and a web of trust where users sign each other’s keys. Choose a format and services to see the processing steps for the sender.





DNSSEC


DNSSEC signs DNS data so a resolver can prove an answer is genuine and unmodified. It does not hide data. Trust flows from the root down: each parent holds a DS record, which is a hash of the child’s key, so a validator starting from the known root key can verify every zone below it.

DNS-Based Authentication of Named Entities (DANE)


DANE publishes a TLSA record, protected by DNSSEC, that pins the server’s certificate or key to its name. A client checks the presented certificate against it instead of trusting every public CA. For SMTP it also stops STARTTLS downgrade. The record has certificate usage, selector (certificate or public key) and matching type (exact, SHA-256 or SHA-512). Paste any text as a stand-in for the certificate.







Sender Policy Framework (SPF)


A domain lists the IP addresses allowed to send its mail in a TXT record. The receiver checks the connecting IP against the record, evaluating mechanisms left to right, and the first match decides. Qualifiers: + pass, − fail, ~ softfail, ? neutral. SPF checks the envelope sender and breaks on forwarding. This checker handles ip4 and all; include, a and mx need DNS and are skipped.





DomainKeys Identified Mail (DKIM)


The sending server hashes the body (bh=), then signs selected headers plus that hash with its private key. The public key sits in DNS at selector._domainkey.domain. A receiver recomputes the body hash and verifies the signature, proving the domain sent it and the signed parts are unchanged. This demo generates a real RSA key in your browser. Change the received copy to see it fail.







IP security (IPsec) overview and architecture


IPsec secures traffic at the network layer, below TCP and UDP, so applications need no changes. It gives access control, connectionless integrity, data origin authentication, replay rejection and confidentiality. Typical uses are VPNs between sites, remote-user access and securing routing.

Authentication Header and Encapsulating Security Payload


Transport mode protects the payload and keeps the original IP header, so it suits host-to-host. Tunnel mode wraps the whole original packet in a new IP header, so it suits gateways and VPNs. AH authenticates almost the whole packet, including parts of the IP header (but not fields that change in transit). ESP does not cover the outer IP header. Choose a combination.





Security associations and combining them


A security association (SA) is a one-way relationship identified by three values: a Security Parameters Index (SPI), the destination IP address and the protocol (AH or ESP). Two-way traffic needs two SAs. Each SA records the sequence counter, anti-replay window, algorithms and keys, lifetime and mode. The receiver rejects repeats with a sliding window. SAs can be combined into bundles by transport adjacency (AH and ESP on one IP packet) or iterated tunneling (tunnels inside tunnels). Four standard cases are: (1) end-to-end between hosts, (2) gateway-to-gateway VPN, (3) a gateway VPN plus end-to-end SAs, and (4) a remote host reaching a gateway and then an internal host.
